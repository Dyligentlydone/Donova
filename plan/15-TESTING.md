# 15 — Testing & Quality

## 1. Test layers
| Layer | Tool | Where | Runs |
|---|---|---|---|
| Unit | vitest | `packages/*/src/**/*.test.ts` | every PR |
| Browser unit (runtime, player) | vitest browser mode (Playwright provider, chromium) | `packages/runtime/test`, `packages/player/test` | every PR |
| Golden render | custom harness `scripts/golden.ts` | `fixtures/**` | every PR (Linux Docker) |
| Determinism | harness | subset of fixtures | every PR |
| Preview↔render parity | harness | subset | every PR |
| CLI matrix | vitest + execa | `packages/cli/test` | every PR |
| Studio e2e | Playwright | `packages/studio/e2e` | every PR (sharded) |
| Cloud integration | docker-compose stack | `apps/api/test` | every PR touching apps/ |
| Agent evals | harness + real LLM | `packages/agent/evals` | nightly |
| Performance | benchmark harness | `fixtures/perf` | nightly, tracked |
| Desktop smoke | Playwright-electron | `apps/desktop/e2e` | release branches |

## 2. Fixtures
```
fixtures/<area>/<name>/
├── project/              # a complete project folder
├── expect.json           # { frames: [0, 15, 45, 89], durationSec, fps, audio?: {...}, lint?: [...], check?: [...] }
└── golden/               # frame_000000.png … committed (Git LFS)
```
Areas: `contract` (timing/visibility/nesting/variables), `adapters` (gsap, waapi, css, lottie, anime, three, custom), `media` (video trims/rates/rotation/HDR/VFR, images, GIF, audio mix/fades/automation/groups), `fonts`, `formats`, `lint/<rule>`, `check`, `studio`, `perf`.

Special media fixtures (generated by `scripts/make-fixture-media.ts` with ffmpeg, never downloaded):
- **barcode video**: each frame encodes its frame number as a row of black/white blocks (decode by sampling pixels) → exact frame-accuracy checks.
- **beep audio**: 1 kHz 10 ms beeps at known offsets → detect onsets in output with ±1 ms check.
- **VFR video**, **rotated phone video** (rotation side data 90°), **29.97 fps**, **HEVC 10-bit**.

## 3. Golden harness
1. Render fixture via producer in the pinned Docker image (`render-worker` image) at `quality: high`, PNG frame extraction of requested frames (`ffmpeg -vf select=eq(n\,N)`).
2. Compare to golden with PSNR (≥ 40 dB pass) and SSIM (≥ 0.98); on fail write diff images to `fixtures/**/__out__/`.
3. `pnpm test:golden --update` regenerates goldens (requires reviewer approval in PR; CI comments a before/after image grid).

## 4. Determinism & parity
- Determinism: render twice in Docker with `-threads 1 -x264-params deterministic=1`; video stream sha256 must match.
- Parity: `snapshot` (preview path, runtime in preview mode with seek) vs render frame at the same time — PSNR ≥ 42 dB.

## 5. Performance budgets (nightly, 8 vCPU Linux)
| Scenario | Budget |
|---|---|
| 30 s 1080p30 text+shapes, auto workers | ≤ 30 s wall |
| 30 s 1080p30 with 1 video + captions | ≤ 45 s |
| 60 s 1080p30 4 workers vs 1 worker | ≥ 3× speedup |
| CLI cold start `--version` | ≤ 150 ms |
| Lint 300-clip project | ≤ 500 ms |
| Studio: open 60 s project to interactive | ≤ 2.5 s |
| Timeline scroll with 500 clips | 60 fps (no frame > 16 ms in trace) |
Regression > 15% fails nightly and opens an issue.

## 6. CI (GitHub Actions)
- `ci.yml`: install (pnpm cache) → build → lint → typecheck → unit → golden (container job with render image) → studio e2e (sharded 4) → cli matrix.
- `nightly.yml`: perf, agent evals, full registry validate.
- `release.yml`: changesets → version → publish npm packages → build/push render image (tag = version + digest) → desktop builds (mac/win/linux) signed → upload update feed → registry CDN deploy.
- Required checks on `main`.

## 7. Definition of done (per task)
1. Code + tests per acceptance criteria.
2. `pnpm build && pnpm test && pnpm lint` green.
3. Docs updated (`docs/`) for any user-visible change (CLI flags, contract, Studio behaviour).
4. Task ticked in `plan/16-BUILD-ORDER.md`; decisions logged.
